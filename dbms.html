Chapter 1

👋 Introduction — What is Data?

What is Data?

Data means raw facts or information. Facts about people, places, things — anything.

Example: facts about one student:

Name: Asif

Age: 21

CGPA: 9.15

Department: CSE

🧠 Think of it like this: data is like ingredients in a kitchen. Alone they are just items. But when we organize and cook them, we get a useful dish!

Why is data important? Because good data helps us make good decisions — which student passed, which product sold most, which day had most visitors. Almost every app you use (YouTube, Instagram, Paytm) runs on data.

🗃️ What is a Database?

A database is an organized place where we store data so it is easy to find, manage, and update.

🧠 Analogy: A database is like a school office cupboard. All student files are kept inside it in order — not thrown around randomly.

Chapter 3

⚙️ What is DBMS?

DBMS = Database Management System.

It is software that helps us store, manage, retrieve, update and delete data from databases.

Popular DBMS software:

MySQL PostgreSQL Oracle SQL Server SQLite

How you talk to a database

You never touch the database directly. The DBMS sits in the middle:

🙋 You ↓ sends SQL ⚙️ DBMS ↓ reads/writes 🗄️ Database

What happens when you send a query?

  1. You write a request (called a query) in SQL.
  2. The DBMS checks it — is the spelling correct? Do you have permission?
  3. The DBMS finds the data inside the database.
  4. The DBMS returns the result back to you.

Why do we need a DBMS?

Imagine saving all college records in normal text files. Chaos! 😵 Compare:

😵 Without DBMS

  • Many messy files
  • Duplicate data everywhere
  • Hard to search
  • Security problems
  • Difficult updates

😎 With DBMS

  • Organized data
  • Fast searching
  • Security (who can see what)
  • Relationships between data
  • Many users at the same time
  • Backup & recovery
Chapter 4

🔗 DBMS vs RDBMS

DBMS

Database Management System

Stores data as files (any format).

RDBMS

Relational Database Management System

Data stored in tables → tables can be related to each other 🔗

🧠 Analogy: In an RDBMS, the Students table and Departments table are linked like friends on Instagram — each student profile "points to" their department page.

Popular RDBMS: MySQL, PostgreSQL, Oracle, SQL Server.

Quick comparison

FeatureDBMSRDBMS
Data storageFilesTables (rows & columns)
RelationshipsNot supportedSupported ✔
Data redundancyMore duplicationReduced via relations
LanguageVariesSQL
ExamplesXML, file systemsMySQL, PostgreSQL, Oracle

Remember: Every RDBMS is a DBMS, but not every DBMS is an RDBMS. This course focuses on RDBMS.

Chapter 6

💬 What is SQL?

SQL = Structured Query Language.

It is the language we use to communicate with relational databases — ask for data, add data, change data.

🙋 You ↓ 💬 SQL Query ↓ ⚙️ DBMS ↓ 🗄️ Database ↓ ✅ Result

Your first query

Every part explained:

  • SELECT → "show me…"
  • * → "all columns"
  • FROM students → "from the table called students"
  • ; → end of the statement (like a full stop.)

In plain English: "Show me all columns and all rows from the students table."

SQL Command Categories

SQL commands come in 5 families. Think of them as toolboxes:

DDL — Structure 🔧

Defines/changes table structure.

CREATEALTERDROPTRUNCATE

DML — Data ✏️

Changes the data inside tables.

INSERTUPDATEDELETE

DQL — Read 👀

Asks questions about data.

SELECT

DCL — Rights 🔐

Controls permissions.

GRANTREVOKE

TCL — Save points 💾

Controls transactions (save/undo).

COMMITROLLBACKSAVEPOINT

In this course we focus on the everyday five: CREATE, INSERT, SELECT, UPDATE, DELETE.

🔍 Filtering — WHERE & Friends

WHERE

WHERE chooses only the rows that match a condition.

🧠 Analogy: LIKE a water filter 🚰 — only what passes the condition comes through.

(Jasmine has exactly 8.50 — not greater than 8.5 — so she is filtered out.)

Operators

Compare

= equal · > greater · < less
>= · <=
<> or != not equal

Combine

AND both true
OR either true
NOT reverse

BETWEEN — a range

IN — any value from a list

Why useful? Instead of writing department_id = 1 OR department_id = 2 OR …, just list values inside IN (). Short and clean.

LIKE — pattern matching

LIKE searches text by pattern, using two wildcards:

% = anything

'A%' starts with A
'%A%' contains A
'%A' ends with A

_ = one character

'A_' A followed by exactly 1 letter
'___' exactly 3 letters

NULL — missing value

NULL means "no value at all" — the field was never filled. It is not zero and not empty text.

Because NULL is "unknown", normal comparisons fail. Use special checks:

⚠️ Never write WHERE cgpa = NULL — it silently returns nothing. Use IS NULL.

DISTINCT — remove duplicates

If 30 students belong to CSE, DISTINCT shows CSE only once. It removes duplicate values from the result.

ORDER BY — sorting

ASC ⬆️ (default)

9.15 → 8.90 → 8.50
smallest to largest

DESC ⬇️

9.15 → 8.90 → 8.50 reversed!
largest to smallest

LIMIT — take only a few rows

Why useful? A table with 10 million rows would crash your app if you fetched it all. LIMIT grabs just a slice (e.g., "top 5 results").

Chapter 13

🚦 HAVING

WHERE filters rows. HAVING filters groups.

You cannot use WHERE on aggregate results (like COUNT) — that's what HAVING is for.

The full journey of a query

Rows ↓ WHERE filters rows GROUP BY makes groups ↓ Groups ↓ HAVING filters groups Final Result
Chapter 14

💞 Relationships Between Tables

Tables connect to each other in three possible ways:

One-to-One (1 : 1)

One row matches exactly one row.

Person → Passport 🛂

One person has one passport; one passport belongs to one person.

One-to-Many (1 : N)

One row matches many rows.

Department ↓
many Students 🎓

One department holds many students — done with a foreign key.

Many-to-Many (M : N)

Many match many.

Students ↕ Courses 📚

A student takes many courses; a course has many students. Built using a third bridge table (e.g., enrollments) holding pairs of IDs.

🤝 JOINs — Combining Tables

Why are JOINs needed?

Real data is split across tables to stay clean. Look — the info we want lives in two places:

Students

student_idnamedepartment_id
101Asif1
102Jasmine2
104Divya—

Departments

department_iddepartment_name
1CSE
2ECE
3MECH

We want: Asif → CSE  Jasmine → ECE

JOIN combines related rows from two tables into one result — using the foreign key link you learned earlier.

INNER JOIN

Returns only the matching rows from both tables. No match → not included.

s and d are nicknames (aliases) for the tables. ON states the match rule.

(Divya has no department → skipped. MECH has no students → skipped.)

LEFT JOIN

Keeps ALL rows from the left table, plus matches from the right. No match? Right side becomes NULL.

RIGHT JOIN

Keeps ALL rows from the right table, plus matches from the left. Mirror image of LEFT JOIN.

FULL OUTER JOIN

Keeps everything from BOTH tables. Matching rows join up; unmatched rows from each side appear with NULLs.

💡 Heads-up: PostgreSQL supports FULL OUTER JOIN directly, but MySQL has no native syntax — there you combine a LEFT JOIN + RIGHT JOIN with UNION.

SELF JOIN

A table joined with itself. Useful when rows refer to other rows of the same table.

🧠 Example: Employees table — each employee has a manager_id, which is another employee's id in the SAME table. Who reports to whom?

The same table plays two roles: e (employee) and m (manager).

CROSS JOIN

Creates every possible combination of rows — no matching rule at all.

🧠 Analogy: Every shirt × every pant combination in a shop 👕👖.

All JOINs at a glance

JOIN TypeMeaningKeeps unmatched rows?
INNER JOINOnly matching rowsNone ❌
LEFT JOINAll left + matchesLeft side ✔
RIGHT JOINAll right + matchesRight side ✔
FULL OUTER JOINEverything from bothBoth sides ✔✔
SELF JOINTable joined with itselfDepends (INNER/LEFT)
CROSS JOINEvery combinationAll combos (no matching)

Bonus: How SQL really runs your query

You write SELECT first, but the database actually processes in this order:

  1. FROM — grab the tables
  2. WHERE — filter rows
  3. GROUP BY — form groups
  4. HAVING — filter groups
  5. SELECT — pick columns
  6. ORDER BY — sort results
  7. LIMIT — trim to N rows

This explains WHY HAVING exists — when filtering happens, aggregates already exist, but plain WHERE ran long ago.
